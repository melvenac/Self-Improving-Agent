## 1. The criteria

### Terms

- **Base:** `origin/master` at the moment C's candidate is frozen, named by SHA in the developer's handoff. It is
  `bf33fe4` today.
- **The merge point:** the single place in the product where a **candidate merge to `master`** is evaluated and a shadow
  verdict is written **before** Aaron's decision is recorded. **On the base it does not exist** (§3, Q1). C must
  implement it as the `shadow-verdict` CLI (CC-19), not inside `runLoop` — `runtime.ts` and `cli.ts` both state the
  runtime never merges.
- **Verdict function:** `computeShadowMergeVerdict` (name is the developer's; the export and behaviour are not), in
  `open-brain/src/harness/`. It is pure: given inputs, it returns one of three outcomes and a reason list. It does not
  read git state and does not write files.
- **Three outcomes** (exact strings, lowercase, hyphenated):
  - `would-merge` — the runtime would have merged this candidate to `master` on the evidence it had.
  - `would-not-merge` — the runtime would have refused the merge.
  - `undefined` — the runtime could not form a verdict. **Never counts as agreement** (T-155 note; CC-12).
- **The verdict artifact:** `artifacts/iterations/<loop>/shadow_merge.json`, where `<loop>` is the loop id from `E_t`
  (`t001` or a human-seat id per BE-1). One file per `(loop, candidate_sha)` pair; a second write is refused (CC-7).
- **The ledger:** `artifacts/shadow-merge/ledger.jsonl`, append-only. Each line is one merge decision episode: the
  shadow verdict, Aaron's decision, timestamps, SHAs, and whether the pair **disagreed** (CC-11). `/sync` checks it
  (CC-13).
- **Criteria SHA:** the git commit of the acceptance-criteria file the candidate was scored against. The verdict
  function reads declared ids from that commit's tree via `parseDeclared` (`declared.ts`), never from `E_t`.
- **A valid / an invalid `E_t`:** `validateEvidence` in `schema.ts`. Human-seat and runtime-loop shapes are both in
  scope once B is in the base.
- **Red at the base** is shown by `git grep` returning no matches, missing paths, or (where noted) an observed CLI
  refusal. A row marked **guard** is green at the base on purpose.

explicitly outside the runtime (`cli.ts` help, D-019). T-155's note and slice-two closeout (§7) said the merge point

is `shadow-verdict prepare`, run at human merge time with `E_t`, `criteria_sha`, and `candidate_sha`.

| Input | Source |
|-------|--------|

| Gate answers | `G_plan.json` / `G_done.json` when present and required by `merge.json` |
